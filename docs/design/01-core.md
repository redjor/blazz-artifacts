# 01 — Core hub

## Goal

Publish a small piece of content (HTML, Markdown, PDF, JSON, ZIP mini-site), often generated by AI, in seconds from a
self-hosted box, and share it in a controlled way: private, secret code, revocable temporary link, or public. Updating
the content must never change its URL.

## Constraints and decisions

The first deployment target was a home NAS with 8 GB of RAM shared with other services, ports 80/443 taken by the NAS
vendor's web server, and a mobile connection without a public IP.

| Decision | Choice | Reason |
|---|---|---|
| Runtime | One Compose stack, image built locally, no VM, no PaaS | A VM would pin several GB of RAM; a PaaS wants ports 80/443 and an orchestrator for a single app. |
| Exposure | Private admin, public content (example: Tailscale serve + Funnel; any reverse proxy works) | No inbound port needed behind CGNAT; the admin never touches the internet. |
| Process model | One Node process, two HTTP servers on two ports, two origins | Simple to run, while keeping admin and untrusted content strictly apart. |
| Storage | SQLite (`node:sqlite`) + files on disk | No native dependency, no database server, trivial backups (`VACUUM INTO`). |
| Server code | TypeScript run directly by Node (type stripping) | No server build step; the image only builds the SPA. |
| Memory budget | `mem_limit: 256m` for the app (about 50 MB used at rest) | Fits next to heavier services on a small host. |

## Isolation of untrusted content

All artifacts share one content origin. Their mutual isolation relies on:

1. a CSP `sandbox` **without** `allow-same-origin` on every content response (PDF excepted, see below), so each document
   runs in an opaque origin;
2. short-lived HMAC-signed paths for files, inherited by relative links, so assets load without cookies;
3. open CORS on signed paths only, because opaque origins send `Origin: null` and module scripts, fonts and `fetch()`
   would otherwise fail; no `Cross-Origin-Resource-Policy`, which would block them;
4. systematic `nosniff`, `no-referrer`, `DENY` framing headers.

Expired signatures redirect to the unsigned path, which re-checks access and re-signs: navigation inside a site survives
expiry. PDFs are served without `sandbox` because browsers refuse to display them in a sandboxed document.

Consequence accepted from the start: `localStorage`, `sessionStorage` and `IndexedDB` are unavailable to artifacts. The
optional "simulated storage" shim covers the common mockup case (`localStorage`/`sessionStorage` in memory, persisted per
tab in `window.name`), with its documented limit.

## Access model

Four visibilities (`private`, `code`, `link`, `public`), signed grant cookies (12 h, capped by link expiry), an access
epoch per artifact to cut every grant and signed path at once, share-link tokens stored hashed and encrypted, attempt
limits per IP and per artifact. A single admin account with a scrypt password, a `__Host-` session cookie, CSRF and
`Origin` checks, and an optional API token for automation.

## Versions

Every upload on an existing slug creates a new version; the switch is one transaction, so visitors never see a partial
state. Markdown and HTML versions are kept forever (small, often iterated); other kinds keep the 10 most recent. Any kept
version can be previewed (pinned signed path, admin only) and restored (pointer switch, no copy). Version numbers are never
reused.

## Thumbnails

Captured on the publisher's machine by the CLI, never on the server (no browser on a small NAS). The server only validates
magic bytes and size, stores the image outside the served files and serves it from the admin origin (and, later, from
folder pages under strict checks). A failed capture never fails a publish.

## Visit statistics

Counted server side on the unsigned entry path only, without scripts or cookies, with bot filtering, a 30-minute
deduplication window, and daily-rotating HMAC fingerprints deleted after two days. Only daily aggregates are kept. The
design favours privacy over precision: "uniques" are distinct visitors per day, summed.

## Out of scope at the time

Secure MDX, Mermaid, KaTeX, duplication, GitHub integration, custom domains with one origin per artifact (which would make
real `localStorage` possible), compiling React/Vue/Svelte sources. Version history and folders, first listed here as later
work, have since been implemented.
